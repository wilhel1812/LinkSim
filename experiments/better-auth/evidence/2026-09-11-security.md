Scope: disposable compatibility experiment only. Application migration and
production cutover remain gated by the outstanding capacity/security work.

fix. Gateway `5224a847-7ddd-47e1-833b-c58bcf8d0d38` and runtime

## Local security checks through the private binding

`durable-local.mjs` reuses its synthetic 1,000-user fixture, mocked provider and
mocked Siteverify responses. No fixture credentials enter the live database.
It now verifies:

- Replayed OAuth callbacks, unknown state, missing state cookie, and a valid
  state paired with another initiation's cookie cannot create a session.
- External, protocol-relative and JavaScript return URLs are rejected.
- Cross-origin or missing-origin logout fails without revoking a valid session.
- Malformed unauthenticated passkey submissions fail without creating sessions.
- Stale sessions cannot generate registration options or remove credentials.
- Issued session cookies are Secure, HttpOnly, SameSite=Lax and host-only.
- A database limiter with one remaining slot survives actual local object
  eviction. Two concurrent calls produce exactly one 200 and one 429; a later
  request remains limited with a positive retry interval. Alternative forwarding
  and identity headers do not reset its key.

These supplement the existing expiry, revocation, renewal and 50-user isolation
checks. Malformed passkey rejection does **not** prove rejection of a replayed
valid WebAuthn assertion or a valid assertion for the wrong RP/origin. Those
ceremony-level negative cases remain outstanding. Simulated schema failure tests
prove fail-closed retry behavior, not actual Cloudflare quota exhaustion.

## Initialization race found and fixed

One pre-fix local eviction burst created 48 Better Auth instances for 50 requests
and read 1,204 rows. A deterministic regression test reproduced 50 initializations
while schema validation was pending. Completed instances were cached, but healthy
initializations in progress were not shared.

The probe now shares the initialization promise while its owning request remains
healthy. Every waiting request awaits schema completion before using the library;
an aborted owner is not reused by subsequent arrivals. Failure removes the pending
entry, allowing retry. No session results or credentials are cached. Request-local
metrics and identities remain isolated, including during shared initialization.

The post-fix local eviction burst used one initialization and 123 reads for 50
successful requests. Renewal remained two queries, four reads and one write;
subsequent checks wrote nothing. This is local compatibility evidence only.
